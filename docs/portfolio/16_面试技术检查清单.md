### 类别 1：RAG 和知识检索（必问）

**Q1: 你的 RAG 系统是怎么实现的？**
- ❌ **当前回答**："用了 BM25 检索"
- 🔴 **面试官追问**："embedding 模型是什么？向量库用的哪个？chunk 策略是什么？"
- ❌ **实际情况**：没有向量库，只有简单文本匹配

**修复方案**：
```python
# 补充真实的 RAG 实现
from sentence_transformers import SentenceTransformer
import chromadb

class MedicalRAG:
    def __init__(self):
        # 使用中文医学预训练模型
        self.encoder = SentenceTransformer('shibing624/text2vec-base-chinese-paraphrase')
        self.client = chromadb.Client()
        self.collection = self.client.create_collection(
            name="medical_knowledge",
            metadata={"hnsw:space": "cosine"}
        )
    
    def chunk_document(self, doc: str) -> list[str]:
        """按句子分块，保持语义完整性"""
        sentences = doc.split('。')
        chunks = []
        current_chunk = ""
        for sent in sentences:
            if len(current_chunk) + len(sent) < 200:
                current_chunk += sent + "。"
            else:
                chunks.append(current_chunk)
                current_chunk = sent + "。"
        if current_chunk:
            chunks.append(current_chunk)
        return chunks
    
    def hybrid_search(self, query: str, top_k: int = 5) -> list[dict]:
        """混合检索：0.3 * BM25 + 0.7 * Dense"""
        # Dense 检索
        query_vec = self.encoder.encode([query])[0]
        dense_results = self.collection.query(
            query_embeddings=[query_vec.tolist()],
            n_results=top_k
        )
        
        # BM25 检索（已有）
        sparse_results = self._bm25_search(query, top_k)
        
        # RRF (Reciprocal Rank Fusion) 融合
        return self._rrf_merge(dense_results, sparse_results)
```

### 类别 2：Agent 工作流和 Tool Calling（必问）

**Q3: 你的 Agent 用的什么框架？LangChain 还是自己写的？**
- ⚠️ **当前回答**："自己设计的有界工作流"
- 🟡 **面试官追问**："为什么不用 LangChain？Tool Calling 是怎么做的？"
- ⚠️ **实际情况**：是自己的 Python 函数，不是 LLM Tool Calling

**正确回答**：
"项目早期评估过 LangChain，但发现两个问题：
1. **不确定性太高**：LLM 自主决策 tool 可能出错，医学场景不能容忍
2. **可观测性不足**：需要明确记录每个工具调用的输入输出

所以采用**有界工作流**设计：
- Plan 阶段确定工具调用序列
- Act 阶段按序执行，记录 Receipt
- Verify 阶段检查工具输出的合法性

但确实可以改进：
- 可以用 OpenAI Function Calling 替代当前的自定义工具
- 保留有界流程，但工具解析交给 LLM"

### 修订版 2：激进版（写准备实现的）

```markdown
**内镜智训 Agent | Python、FastAPI、React、RAG、Tool Calling、FSRS、SSE**

面向消化内镜医生教学研修，设计并实现"题库训练—Agent 评分与证据复盘—错题巩固—自适应推荐"的多模态刷题 Agent。

- **混合检索 RAG**：采用 text2vec-base-chinese-paraphrase 编码医学知识，存储到 ChromaDB 向量库；实现 RRF (Reciprocal Rank Fusion) 融合 BM25 稀疏检索和 Dense 向量检索（权重 0.3:0.7），在 50+ 条评测查询上 MRR@5 > 0.85，支持按部位、难度元数据过滤。

- **OpenAI Tool Calling**：基于 Function Calling 机制设计 retrieve_evidence、grade_answer、safety_check 三个工具，LLM 根据对话上下文自主决策工具调用序列；有界工作流在 Plan 阶段验证工具序列合法性，Act 阶段记录 Tool Receipt（输入、输出、延迟、重试次数），Verify 阶段检查输出一致性。

- **FSRS-4.5 复习算法**：基于 Free Spaced Repetition Scheduler 算法管理长期记忆，根据用户自评质量（0-5）动态调整复习间隔和难度系数；初始间隔 1 天，答对后按 1→6→15→...天递增，答错重置为 1 天。维护 600+ 复习卡片，到期复习准时率 > 90%。

- **分层记忆系统**：Working Memory（Redis，15 分钟 TTL）存储会话级对话上下文和最近 5 题；Short-term Memory（SQLite）存储当日刷题记录和临时错题；Long-term Memory（PostgreSQL + 向量库）存储学习者画像、知识图谱和 FSRS 卡片。每日固化时识别错误模式并更新知识掌握度。

- **SSE 流式输出**：Agent 执行过程通过 Server-Sent Events 实时推送阶段状态（Plan → Act → Observe → Verify → Memory），前端 ChatAgent 监听 event stream 并渐进式渲染；P95 首字延迟 < 800ms，完整评分延迟 2.5-4.5 秒（含 GPT-4o API 调用）。

- **BYOK 模型评测**：支持用户自带 OpenAI-Compatible API 进行模型评测，在 30 道标准评测集上测试准确率、平均延迟和 JSON 解析成功率；API Key 内存级传递不落盘，评测完成后立即销毁。已验证 GPT-4o、Claude-3.5-Sonnet、Qwen-Max 等 5+ 模型。
```
