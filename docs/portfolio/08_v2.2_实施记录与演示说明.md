# v2.2 实施记录与演示说明（含 v2.2.1 前端纠偏交接）

## 本轮产品定位

v2.2 把主流程从“5 个病例工作台”改回“内镜医师刷题 Agent”。当前 `/study` 是过渡实现：它已经能承载题库、筛选、作答、智能带教和复习建议，但仍把多个职责塞在同一页，不能作为最终产品交付。v2.2.1 将产品收口为“学习总览 → 题库 → 刷题工作台 → 模型评测”四个用户模块；`/workbench` 只保留为开发者技术详情，`/lab` 迁移为 `/eval` 的用户评测页。

## v2.2.1 UI/信息架构纠偏（交接重点）

## 演示建议（当前过渡版，仅用于核对后端能力）

1. 当前版本打开 `/study` 只能用于核对后端题池：展示当前题池、纯文本题、图文题、待复习；不要把这个页面当作最终 UI。
2. 在左侧切换“食管/胃/小肠”和“单选/多选/判断/问答评分”，证明题型和内容模态解耦。
3. 选择纯文本题，提交答案，展示即时评分和复习要点。
4. 选择图文题，说明图片只在需要视觉推理时出现，尺寸保持统一。
5. 在右侧智能带教里点击“拆知识点/排除干扰项/给提示”，证明 Agent 进入刷题过程，而不是提交后才聊天。
6. 最后跳转 `/workbench` 看受控工具链路，跳转 `/lab` 看模型评测入口。v2.2.1 完成后改为从 `/` → `/banks` → `/practice` → `/eval` 演示。

## 参考依据

- Anki 的 deck/note/card/template 思路用于解释题库内容与展示卡片应解耦。
- Moodle Question Bank 用于校准题库分类、题型和预览/管理入口。
- Qdrant hybrid search/rerank 用于后续 RAG 评分链路规划；本轮先实现可替换的数据与评分入口。
- UI/交互参考 [ZeroQCM](https://github.com/KNIGHTABDO/zeroqcm) 的题目—收藏—复习闭环、[Stepwise QBank](https://github.com/yagamilight-pk/stepwise-qbank-complete) 的题库卡/全屏会话，以及 [Lumi AI Editor](https://github.com/Lumieducation/Lumi-AI-Editor) 的右侧 AI chat drawer；只借鉴信息层级和交互模式，不复制其业务数据或代码。
