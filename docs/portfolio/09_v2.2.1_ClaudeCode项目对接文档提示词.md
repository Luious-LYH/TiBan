## 三、锁定后的产品结构

产品名称：**内镜刷题 Agent · EndoTutor**

主导航严格只有四项：

| 路由 | 用户看到的名称 | 只解决什么问题 |
|---|---|---|
| `/` 或 `/overview` | 学习总览 | 我今天该做什么、哪些知识点待复习 |
| `/banks` | 题库 | 我有哪些题库、每个题库进度如何、如何导入新题 |
| `/practice?bank_id=...&session_id=...` | 刷题工作台 | 我现在答哪一道题、如何提交、如何得到讲解 |
| `/eval` | 模型评测 | 我选择哪套评测题、如何一次性调用自己的模型、结果如何 |

`/workbench` 可以保留为开发者详情别名，但不放进普通用户主导航；`/lab` 可以重定向到 `/eval`。不要新增第五个业务入口。

## 四、页面 PRD 与低保真原型

### 1. 学习总览 `/`

页面目的：让用户 5 秒内决定下一步。

建议结构：

```text
┌ 顶栏：EndoTutor                         [题库] [刷题工作台] [模型评测] ┐
│ 早上好，今天完成 3 道题即可保持学习节奏                            │
│ [今日任务 3/5] [待复习 6] [本周正确率 78%] [连续 4 天]               │
│ [继续上次练习]       [开始到期复习]                                  │
│ 我的题库                                                               │
│ [食管基础] [胃部观察] [小肠胶囊] [+ 导入题库]                       │
│ 最近练习 / 薄弱知识点 / 今日建议                                     │
└──────────────────────────────────────────────────────────────────────┘
```

要求：

- 题库采用书本式矩形卡片：名称、部位、题量、题型标签、完成度、最近练习时间和“开始练习”。
- 统计卡只讲进度，不暴露内部字段；空数据、首次使用和断线都有可理解状态。
- 点击题库卡进入 `/practice?bank_id=<id>`；“查看全部题库”进入 `/banks`。
- 首页没有题干、选项、提交、原始 JSON、模型 API、Agent trace。

### 2. 题库 `/banks`

页面目的：像刷题软件的题库目录，不像接口管理台。

建议结构：

```text
题库                                             [导入题库]
[全部] [官方教学] [我的题库]       搜索题库/知识点

[食管基础]       42 题  68%        [单选][判断][简答] [开始练习]
[胃部观察]       38 题  51%        [单选][多选][图文] [开始练习]
[小肠胶囊]       26 题  20%        [判断][简答]       [开始练习]

导入题库弹窗：JSONL / CSV / Markdown / Anki CSV
步骤：选择模板 → 粘贴/上传 → 字段校验 → 预览 → 保存为草稿
```

要求：

- 食管、胃、小肠是首批题库，不要把“末观察视野/异常计数/器械分布”当一级题库。
- “官方教学”和“个人题库”分开标记；benchmark 评测集不出现在教学题库卡片中。
- 导入弹窗显示人话错误：第几行缺题干、答案不在选项、题型不支持；同时显示通过题数、纯文本/图文数和内容摘要。
- 题库页可以有题库详情抽屉（知识点分布、题型分布、来源和版本），但默认折叠技术字段。

### 3. 刷题工作台 `/practice`

页面目的：一次只完成一个题库/会话，所有注意力放在作答。

建议结构：

```text
食管基础 / 今日练习                         3 / 10   [收藏] [退出]

┌──────────────────────────────┬──────────────────────────┐
│ 题型：单选       难度：基础    │ 智能带教                  │
│ Barrett 食管记录时应优先写入… │ “卡住了吗？我可以给提示” │
│                                │ [拆知识点] [给提示]       │
│ ○ A ...                        │                          │
│ ○ B ...                        │ 消息滚动区               │
│ ○ C ...                        │                          │
│ ○ D ...                        │ 输入：问问这道题          │
│ [提交答案] [下一题]             │ [发送] [停止生成]          │
└──────────────────────────────┴──────────────────────────┘
```

要求：

- 主体只显示当前题，纯文本题不渲染空图片；图文题图片统一容器比例，支持放大、加载失败和 alt。
- ChatAgent 是独立 panel/drawer：独立滚动、独立关闭、独立 loading/error/retry/cancel；桌面宽 320—360px，移动端变为底部 sheet。
- 进入页面时 Tutor 默认收起，只显示一行提示和快捷按钮；点击后自动带入 `question_id`、题干、当前选项和会话状态，用户不用重复描述。
- 提交前允许提示、术语解释、比较选项和检查思路；禁止读取或泄露标准答案。提交后才显示逐项讲解、错因、证据和“加入复习”。
- 提交结果在当前会话内展开或进入结果抽屉：正确/需要复盘、得分、知识点、解析、下次复习时间、再练一题。
- 刷新页面可凭 `session_id` 恢复当前题和进度；提交按钮防重复点击。

### 4. 模型评测 `/eval`

页面目的：给面试官看清“测了什么、是否真的调用、每题结果如何”。

建议结构：

```text
模型评测
[选择评测集：Endoscopy-mini-v1 ▼] [题数 10]
模型连接（一次性使用，不保存）
[兼容 OpenAI 的地址] [模型名] [API Key••••] [测试连接]
[开始评测]

状态：未开始 / 调用中 3/10 / 已完成 / 部分失败
汇总：事实准确率 | JSON 有效率 | P50/P95 | 失败题数
逐题表：题号 | 题型 | 模型输出摘要 | 得分 | 延迟 | 错误
```

要求：

- 未真实调用不得显示模型得分；只显示“尚未开始”或“配置预览”。
- API key 只驻留内存，页面刷新即清空，后端不写入日志、数据库、artifact；展示脱敏状态而不是密钥。
- 评测集、教学题库、RAG 知识库三套 manifest 分开；参考答案只在服务端评分，不放进模型请求。
- 评测失败要区分无 key、认证失败、超时、429、无效 JSON，不自动换模型掩盖失败。

## 五、题库数据和题型契约

不要把“病例”当题库唯一单位。推荐抽象：

```text
DomainPack（内镜）
  └─ QuestionBank（食管/胃/小肠）
       └─ Note（知识点内容，可含图片）
            └─ Question/Card（某一次考法）
                 └─ Attempt（用户作答事件）
```

最小字段：

```json
{
  "id": "eso_barrett_001",
  "bank_id": "esophagus-teaching",
  "question_type": "single_choice",
  "modality": "text",
  "stem": "题干",
  "options": [{"id": "A", "text": "选项"}],
  "answer": ["A"],
  "explanation": "为什么",
  "knowledge_tags": ["Barrett食管", "报告记录"],
  "rubric": [{"id": "fact_1", "expected": "…"}],
  "source_refs": [{"doc_id": "…", "page": 12}],
  "media": [],
  "version": "1.0.0"
}
```

兼容题型：`single_choice`、`multiple_choice`、`true_false`、`short_answer`；预留 `fill_blank`、`matching`、`image_region`。`modality=text|image|text_image`，不能用题型名推断是否有图片。

导入优先顺序：JSONL 真源 → CSV/Anki CSV 易用入口 → Markdown 人工编辑入口 → 后续 QTI 适配器。导入必须经过 `validate → draft → preview → publish`，不能导入即上线。

## 六、Agent、RAG、记忆和评测的最低可讲实现

### 1. Tutor Agent

前台只展示“智能带教”一个角色，后台按意图调用工具：

- `get_question_context`：读取题目、选项、题型和学习目标。
- `retrieve_knowledge`：检索当前题相关知识片段。
- `explain_option`：比较某个选项，不提前给标准答案。
- `grade_answer`：客观题走确定性 grader，简答题走 rubric + 证据 + 可选 LLM Judge。
- `update_learning_state`：提交成功后写入 attempt、知识点掌握度和复习卡。
- `schedule_review`：根据 rating 更新下一次复习时间。

最小工作流：`识别意图 → 读取当前题 →（需要时）检索 → 生成提示/讲解 → 返回引用和下一步`。不要为了显得高级而让多个 Agent 自由群聊。

### 2. RAG 评分链路

题目讲义和参考资料单独建知识库；每个 chunk 继承 `bank_id/body_part/knowledge_tag/source_doc/page/version`。建议实现：

```text
标题/章节切 parent → 150—300 中文 token child
→ dense embedding + BM25/sparse 召回
→ RRF/加权融合 Top-K
→ rerank Top-N
→ 证据片段 + source_ref 注入 Judge
→ 输出 score、命中 rubric、遗漏、矛盾和引用
```

先允许本地轻量实现（BM25 + 余弦/假向量适配器），接口保持可替换；最终要能对比 sparse、dense、hybrid、hybrid+rerank 的 Recall@K/MRR，并在 UI 用“参考资料”卡展示，不显示分数。

### 3. 记忆分层

- 会话记忆：当前题、当前选项、最近几轮 Tutor 消息；会话结束可清理。
- 作答事件：question_id、answer、score、错因、时间；可审计、不可覆盖。
- 学习画像：知识点掌握度、常见错因、最近复习时间；从多次作答聚合。
- 复习卡：`rating/difficulty/stability/retrievability/due_at`；答对/答错只在提交成功后更新。

Tutor 预提交请求不能写长期记忆；“用户明确收藏/加入复习”才产生相应副作用。

### 4. 模型评测

BYOK 请求使用临时凭证、评测集固定版本、答案服务端保存。每题记录 `request_id/question_id/status/latency/raw_output_summary/parsed_output/score/error`；不把完整 key 或患者数据写入 artifact。
