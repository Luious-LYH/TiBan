# 从这里开始：作品集阅读与演示地图

本目录服务两类读者：需要快速上手项目的维护者，以及会追问实现和实验边界的技术面试官。

## 一句话定位

**内镜刷题 Agent · EndoTutor** 是一个面向消化内镜医生学习的题库与智能带教 Demo。它以传统刷题业务为主线：题库、作答、错题、收藏和间隔复习；以受控 Agent 为加分项：在当前题上下文中给提示、解释选项、按 Rubric 评分并安排复习。模型评测是独立入口，不与教学题库混用。

项目不提供自主临床诊断，所有医学输出均为教学或医生复核前辅助。

## 先看这条产品主链（v2.2.1 目标）

```text
/ 学习总览
  今日任务 / 待复习 / 进度 / 题库书本卡
       ↓ 点击题库卡
/banks 题库
  食管 / 胃 / 小肠 / 个人导入 / 题量与完成度
       ↓ 开始练习，携带 bank_id + session_id
/practice 刷题工作台
  题目与作答区  ↔  右侧独立 ChatAgent
       ↓ 提交后
  逐项讲解 / 错题 / 掌握度 / 下次复习
       ↓ 技术追问或模型实验
/eval 模型评测
  冻结评测集 / 一次性 API / 逐题结果 / 指标
```

当前过渡版可从 **`/study`** 核对后端题池；完成 v2.2.1 后现场应从 **`/` → `/banks` → `/practice` → `/eval`** 开始。这样先说明“我有哪些题库、今天该做什么”，再展示“刷题时 Agent 如何陪练”，最后用独立评测证明“如何验证模型”。

## 口径边界（必须区分）

- **Agent 100%**：是固定确定性回归的任务/检索/恢复/重放/安全通过率；主演示为规则 Runtime，`model_calls=0`，不能描述为模型准确率。
- **模型实验**：冻结测试集只有 3 张公开教学图像。可以说“在该冻结小样本上观察到”，不能说泛化能力、临床能力或医学有效性。
- **学习状态**：UI 发起作答时传 `commit_memory=true`，结果写到 `backend/runtime/data/portfolio_study_state.json`；`/api/demo/reset` 可清理。离线回归与 Replay 不写入，以免污染结果与进度。
