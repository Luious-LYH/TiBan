# v2.2.2 ClaudeCode 改造审查报告与执行提示词

> 审查日期：2026-08-27  
> 审查对象：`feat/portfolio-v2.1` / v2.2.1 现状  
> 文档用途：交给 ClaudeCode 执行 v2.2.2；本报告本身不修改业务代码。  
> 产品边界：医学教育与医生复核前辅助 Demo，不是自主诊断系统。

## 1. 结论先行

当前版本不能直接作为简历 Demo 展示。原因不是功能数量少，而是“界面、数据、Agent 证据链”没有形成一个可信闭环：

1. 页面大量使用 Tailwind 类名，但 `frontend/package.json` 没有 Tailwind 依赖、配置或构建链，页面实际接近无样式 HTML。
2. 题库卡片写死“食管 42 题、胃 38 题、小肠 26 题”，后端 `/api/question-banks` 实际返回的是一个 58 题统一题库，展示数据失真。
3. 刷题页的字段口径不一致：前端期待 `type/question_id` 和对象选项，后端返回 `question_type/id` 和字符串选项；`bank_id` 也没有真正筛选题目。
4. 题库导入页读取了错误的返回字段，真实校验结果无法展示，用户无法判断哪些题可以导入。
5. 模型评测页是硬编码进度和分数，没有调用真实后端评测产物；未调用就不能显示完成率、延迟等指标。
6. Agent 目前是固定的受控 Python 工作流，具备 Plan→Act→Observe→Verify→Memory、工具回执、重试和回放，但没有真正的 dense embedding、向量库、混合检索或 LLM Tool Calling。可以包装成“受控工作流 Agent + 可解释检索 + 原子事实评分”，不能包装成完整自主 Agent 或生产级 RAG。
7. 记忆已有错题、画像、复习到期等数据，但没有清晰的 Session Memory / Learner Profile / Review Card 分层，也不能宣称完整 FSRS。

v2.2.2 的目标应是：只保留四个清晰模块，用一条真实可演示的主线完成“选题库 → 刷题 → 右侧带教 → 提交反馈 → 错题/复习更新”，并让每个技术点都有后端证据、可读 UI 和可复现验收。

## 2. 当前版本事实审计

### 2.1 前端与工程问题

| 问题 | 事实 | 影响 | v2.2.2 处理 |

### 2.2 题库与刷题问题

后端已有统一题目数据和导入校验接口，但前端没有把它们当作唯一事实源。

- 题库摘要不能继续硬编码；题目数、题型分布、部位和进度必须由 `/api/question-banks` 或等价聚合接口返回。
- 题库不能只剩“诊断报告描述”。最低要支持纯文本知识题、图文题和后续可扩展题型：单选、多选、判断、简答/评分、报告表达修订。
- 题库应按“食管基础、胃部观察、小肠与胶囊、结直肠基础、通用内镜知识”等可扩展大类组织；部位只是 metadata，不应把所有题强行做成病例报告题。
- 每道题应有 `id/title/question_type/question/options/answer/explanation/knowledge_points/body_part/modality/image_url/image_alt/difficulty/tags/source/version`；前端只依赖这一套规范。
- `GET /api/practice/questions` 必须真正接收 `bank_id`、`question_type`、`body_part`、`only_wrong`、`only_favorites`、`limit`。
- 提交接口必须接收对象化的 `question_id` 和统一的 `selected_answer`，返回 `is_correct/score/explanation/fact_feedback/error_tags/next_recommendation/profile_updated/doctor_review_required/safety_notice`。
- 选择题按标准答案确定性评分；简答题采用 rubric 原子事实评分，必要时由可选模型做语言辅助，但不得让模型随意改写标准答案。

### 2.3 题库导入问题

当前前端读取 `ok/valid/passed/failed/errors/preview`，后端实际返回 `accepted_count/rejected_count/ready_to_publish/items/issues/summary`，因此有效内容会显示为“通过 0 题”。模板字段也错读了 `templates[format]`，后端实际在 `templates.examples[format]`。

v2.2.2 必须采用“上传/粘贴 → 预检 → 逐行问题 → 预览 → 保存草稿”的流程：

- JSONL、CSV、Markdown 三种格式都保留。
- 纯文本题不需要图片；图文题必须允许 `image_url` 或本地公开教学图片映射，并要求 `image_alt`。
- 校验结果展示真实 accepted/rejected 数量、行号、字段问题和预览；无后端时明确显示“校验服务不可用”，不能伪造通过数量。
- 保存动作只能在 `ready_to_publish=true` 时启用；保存为草稿，不默认发布。
- 导入题库不能携带患者姓名、住院号、检查号或真实病例隐私信息。

### 2.4 模型评测问题

当前 `/eval` 页面自行用 `setInterval` 模拟进度并硬编码 10 题、80% 等结果，没有调用 `v3Api.customModelEvaluate`。这会造成“页面看起来评测完成，但后端没有任何请求”的严重面试风险。

根据 `code/AGENTS.md`，模型评测当前是 mock/reserved 能力，v2.2.2 不应偷偷把外部 API 调用伪装成真实生产评测。正确处理是：

- 平台已有 GPU Artifact 时，调用 `/api/models/evaluation`，只展示 Artifact 返回的真实指标、样本范围、模型配置和时间戳。
- 自定义模型区标记为“临时接入预留/演示”，只有后端真正返回结果才展示结果；没有结果就显示“尚未运行”，不生成占位分数。
- API Key 只能内存使用、不可落盘、不可进入日志、审计或 URL；页面不展示完整 key。
- 评测集要显示版本、题数、模态覆盖和评分协议；不能把测试样本答案直接展示给模型或用户。
- 算法岗简历只写已有 Artifact 能证明的量化结果；没有新实验就不能写“提升 xx%”。

## 3. Agent 技术能力的真实边界

### 3.1 当前可以写进简历的能力

`portfolio_agent_runtime.py` 已有：

- 受控 Plan→Act→Observe→Verify→Memory 工作流；
- `retrieve_case_evidence`、`fact_rubric_grader`、`safety_guard` 三类工具；
- Tool Receipt、一次重试、错误恢复和 checkpoint replay；
- 原子事实 rubric、稀疏检索、证据 ID 和可解释反馈；
- 运行态与版本化样本隔离、离线回归评测、Recall@K、Recovery Rate、Safety Probe、F1。

建议简历口径：

> 面向内镜医师刷题场景，设计受控工作流 Agent，将题目解析、证据检索、原子事实评分、安全边界检查和学习画像更新拆为可观测步骤；通过结构化工具回执、失败重试与 checkpoint 回放保证反馈可解释、可复现。

### 3.2 当前不能写的能力

除非 v2.2.2 真的实现并有测试，否则禁止写：

- 向量数据库 / dense embedding / hybrid RAG / reranker；
- OpenAI/Claude 原生 Function Calling；
- 完整 FSRS 或 Anki 同等级调度算法；
- 自主多 Agent 协作；
- 真实 BYOK 全量评测；
- SSE 流式输出；
- 生产级医疗诊断、临床决策或患者服务。

### 3.3 v2.2.2 可选的最小技术升级

如果 ClaudeCode 有足够时间，优先做“可替换接口 + 小规模真实实现”，不要堆名词：

```text
题库/讲义/参考资料
  → parent document 与 150–300 中文 token child chunk
  → metadata（body_part、question_id、source、version）
  → sparse BM25 + 本地 embedding dense top-k
  → RRF/加权融合
  → top-n rerank（可先用轻量 cross-encoder 或确定性规则）
  → 证据片段注入带教/简答评分
  → 返回来源标题、片段和分数，供用户展开查看
```

接口可以先用本地 SQLite/JSON + FAISS/Chroma 适配器；关键是 `Retriever` 接口、可替换实现和 Recall@1/3/5 回归集。没有真正运行的 embedding 或向量库，不得在 UI 或简历中声称已实现。

Agent 路由建议：`hint`（提交前不给答案）→ `explain`（提交后解释错因）→ `chat`（围绕当前题追问）；评分闭环必须是“检索 → rubric/规则评分 → 安全过滤 → 记忆写入”，而非单纯聊天。

### 3.4 记忆分层建议

采用四层命名，避免把所有数据都叫 Memory：

1. **Session Memory**：当前题、当前答案、最近 5 条带教消息，只服务当前会话，可随会话结束清理。
2. **Attempt/Event Log**：每次作答事件追加写入，不覆盖历史，包含题目、答案、分数、来源和时间。
3. **Learner Profile**：跨会话的知识点掌握度、错误模式、题型偏好和最近薄弱项。
4. **Review Card**：题目级 rating、difficulty、stability、retrievability、due_at。若只实现简化间隔规则，命名为“复习计划”或“FSRS-lite”，不得写完整 FSRS。

带教提示默认不写入长期画像；提交、收藏、加入复习才触发持久化。这样既能解释短期/长期记忆，也能避免把无关闲聊污染学习画像。

## 4. v2.2.2 产品与页面范围锁定

### 产品主线

```text
学习总览 → 选择题库 → 选择题型/模式 → 刷题工作台
→ 右侧带教 Agent 提示/追问 → 提交答案 → 反馈与证据
→ 错题/收藏/复习计划更新 → 返回总览
```

### 只保留四个主模块

| 模块 | 用户任务 | 必须保留 | 不放在首屏 |
|---|---|---|---|
| 学习总览 | 知道今天学什么、哪里需要复习 | 今日任务、待复习、连续学习、最近记录、题库卡片 | 原始 JSON、工具名、完整评测表 |
| 题库中心 | 找到并管理可用题库 | 题库卡片、部位/题型筛选、导入题库、进度 | 直接刷题、Agent 内部日志 |
| 刷题工作台 | 作答并得到可行动反馈 | 题干、选项/输入、进度、提交、下一题、右侧独立 ChatAgent | dense score、Call ID、原始 tool output |
| 模型评测 | 查看已有 Artifact 或预留评测 | 评测集、运行状态、真实指标、结果来源 | 硬编码分数、假进度、明文 key |

### UI 视觉方向

不要参考 Anki 的老式密集列表，也不要复制任何开源项目。可借鉴 Dify 的工作流分区、Open WebUI/LibreChat 的独立对话区、现代临床 SaaS 的留白和信息层级：

- 浅灰背景、白色卡片、深海军蓝文字、青绿色主色；
- 8–12px 圆角、轻阴影、明确主按钮，避免霓虹、紫色渐变和玻璃拟态；
- 首屏只保留一个主 CTA；高级信息渐进式展开；
- 桌面端刷题页采用“题目主区 + 320–360px ChatAgent 侧栏”，移动端变为 bottom sheet/抽屉；
- 题库卡片像课程/书本封面，有标题、部位、题型徽章、真实题数、进度和“开始练习”；
- 图片使用统一容器（固定最大高度、`object-fit: contain`、懒加载、alt），不拉伸、不让图片挤压作答区；
- 页面文案面向医生用户，技术证据放到“查看本次讲解依据/查看运行详情”折叠面板。

参考资料（只学习交互原则，不复制视觉）：[LangGraph 持久化与人机协同](https://langchain-ai.github.io/langgraph/index.html)、[LangGraph Checkpointer/Store 记忆分层](https://langchain-ai.github.io/langgraph/concepts/time-travel/)、[LlamaIndex 混合检索与重排](https://developers.api.llamaindex.ai/api/resources/beta/subresources/retrieval/methods/retrieve/)、[FSRS 算法说明](https://github.com/open-spaced-repetition/awesome-fsrs/wiki/The-Algorithm)、[Dify 工作流与人工审核](https://www.dify.ai/workflows)、[Open WebUI 开源项目](https://github.com/open-webui/open-webui)、[LibreChat 开源项目](https://github.com/danny-avila/LibreChat)。

## 5. 推荐 API 与类型契约

前后端只保留一套字段；旧字段可在后端兼容转换，但不能继续让页面各写一套。

```ts
type QuestionType = 'single_choice' | 'multiple_choice' | 'true_false' | 'short_answer' | 'report_revision'

type QuestionOption = { id: string; text: string }

type Question = {
  id: string
  bank_id: string
  title: string
  question: string
  question_type: QuestionType
  options?: QuestionOption[]
  answer?: string | string[]
  explanation: string
  knowledge_points: string[]
  body_part: string
  modality: 'text' | 'image_text' | 'image'
  image_url?: string
  image_alt?: string
  difficulty?: 'easy' | 'medium' | 'hard'
  tags: string[]
}

type QuestionBank = {
  id: string
  name: string
  description: string
  body_parts: string[]
  modality_counts: Record<string, number>
  question_type_counts: Record<QuestionType, number>
  total: number
  completed: number
  progress: number
  version: string
  status: 'draft' | 'published'
}
```

关键接口：

- `GET /api/question-banks`：真实题库摘要；
- `GET /api/practice/questions?bank_id=...`：按题库返回题目；
- `POST /api/practice/submit`：统一提交并返回反馈；
- `POST /api/practice/tutor`：真实调用带教服务或明确标注规则回退；
- `POST /api/question-banks/import/validate`：显示真实校验结果；
- `GET /api/models/evaluation`：已有 Artifact；
- `POST /api/models/custom-evaluate`：仅在后端确实执行并返回结果时显示结果。

所有医疗教育输出保留：

```json
{
  "doctor_review_required": true,
  "safety_notice": "仅供教学训练或医生审核前辅助，不作为独立诊断依据。"
}
```

## 6. Keep / Cut / Defer

### Keep（v2.2.2 必须完成）

- 四模块路由和现代卡片式 UI；
- 真实题库卡片和可扩展题库 schema；
- 纯文本、图文、单选、多选、判断、简答/报告表达题；
- 题库选择到带 `bank_id` 的刷题会话；
- 选择题确定性评分、简答题 rubric 反馈；
- 右侧独立 ChatAgent，提示/讲解/追问真实走后端；
- 错题、收藏、复习到期和学习画像更新；
- 真实导入预检、模板下载、错误行提示；
- 真实评测 Artifact 展示与明确的未运行状态；
- loading/empty/error/retry/disabled/fallback、安全提示和响应式布局。

### Cut（从用户主界面删除）

- 首页堆叠全部题目；
- `Run/Receipt/Memory Delta/Evidence ID/model_calls` 等开发词；
- 无后端请求的假进度、假分数和假题库数量；
- 把所有题都做成诊断报告描述；
- 首屏展示完整 JSON、工具参数、模型内部上下文预算；
- 直接把“示例能力测评题”冒充真实医生课程题库。

### Defer（独立实验，不阻塞 v2.2.2）

- 完整 FSRS 参数拟合；
- 大规模向量库和多模态索引；
- 多 Agent 自主协作；
- 真实外部 BYOK 全量评测；
- SSE token 级流式；
- 新 GPU 微调/蒸馏实验。已有服务器 Artifact 可以单独展示，不能在没有结果时写入简历。

## 7. 验收标准

### P0 用户流程

- [ ] 首页不直接刷题，只展示进度、待复习和题库入口。
- [ ] 点击任一题库后进入 `/practice?bank_id=<真实ID>`，题数和题目确实属于该题库。
- [ ] 至少能完成单选、多选、判断、简答各一题：选择/输入 → 提交 → 反馈 → 下一题。
- [ ] 刷题页桌面端右侧始终有独立 ChatAgent；移动端可打开抽屉。
- [ ] “给我提示”会真实触发 `/api/practice/tutor`，不能只填充输入框。
- [ ] 提交后能看到结果、解释、知识点、下一步建议，并写入错题/画像/复习状态。

### P0 数据真实性

- [ ] 题库卡片不再出现任何前端硬编码题数。
- [ ] 导入一条合法 JSONL 后显示 `accepted_count=1`；非法行显示行号和问题；后端不可用时明确显示不可用。
- [ ] `/eval` 未收到后端结果时不显示完成分数；已有 Artifact 的指标带来源和时间。
- [ ] 所有 fallback 都有可见来源标记，不冒充 provider 或真实模型。

### P0 视觉与可用性

- [ ] 不再出现未生效的 Tailwind 类；`npm run build` 通过。
- [ ] 375px、768px、1280px 宽度无横向滚动；图片比例统一；主要按钮和输入控件 ≥44px。
- [ ] 颜色不是唯一状态表达方式；所有图标按钮有 aria-label；键盘可完成主要流程。
- [ ] 普通用户看不到内部字段名和英文调试术语；开发详情可折叠查看。

### P1 技术证据

- [ ] Agent 每次运行返回阶段、工具、结果来源和安全状态；失败能重试或给出明确错误。
