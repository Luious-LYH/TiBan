# 三分钟演示脚本：从刷题业务到 Agent 证据

演示前打开 `/study`。如需每次都得到相同起点，可在演示前请求 `POST /api/demo/reset`；它只清理运行态学习记录，不修改题库种子。

## 0:00–0:25 研修中心：为什么是这道题

“这是一个内镜医师研修 Agent，不是把 Chat 窗口套在病例上。研修中心保留了刷题产品应有的今日计划、题库、错题、收藏和复习业务。”

- 指向“今日自适应训练”：说明推荐优先级是错题、复习到期、未完成题和薄弱维度。
- 说明病例均为公开脱敏教学样例，当前选择“食管黏膜观察与 Z 线定位”。
- 点击“开始练习”，进入 `/workbench?case=case_esophagus_landmark`。

## 0:25–0:55 工作台：先由研修者独立作答

“题目要求按部位标志、黏膜表现、阴性发现和复核边界作答。这里保留传统主观题的独立观察，而不是先给出答案。”

- 为展示错题闭环，输入一条**刻意不完整但保留复核边界**的观察：`可见 Z 线；需结合完整检查由医生复核。`
- 提交后等待最终 Run 到达；评分不会在阶段流完成前提前显示。

## 0:55–1:35 Agent Activity：执行而非动画

展开本次 `run_id` 和真实 NDJSON 阶段流：

- **Plan**：目标、固定工具顺序与教学边界。
- **Act / Recovery**：`retrieve_case_evidence`、`fact_rubric_grader`、`safety_guard`；Tool Receipt 有 `attempt`、`error_code`、`retryable` 和 `recovered_from_call_id`。本次正常路径不一定触发恢复，故障恢复的可重复证据在 `/lab`。
- **Observe / Verify**：命中 Evidence ID、事实 P/R/F1、遗漏事实与医生复核边界。
- **Memory**：本次 UI Run 带 `commit_memory=true`，将分数、遗漏事实、复习间隔和能力维度 Delta 写入可重置运行态；这里不是把答案塞进长期提示词。

可展开 Context Manifest 和 Usage Ledger，强调主演示是 `deterministic_rule_runtime`、`model_calls=0`；不要把规则执行称为在线模型推理。

## 1:35–2:05 题库闭环：错题、进度与下一题

- 点击“返回研修中心”或导航回 `/study`。
- 展示今日进度增加、该病例已有最佳分和尝试记录；“错题本”出现本次遗漏事实，并进入待复盘队列。
- 说明答对同一病例会将其从错题状态中移出，并按分数更新下次复习间隔；“下一题”来自当前学习状态，而非静态顺序。

## 2:05–2:25 诊断可复现性：工具与 Replay

- 回到刚才的 Run，打开检索 Receipt：展示 query、数据集/部位元数据过滤、rank、score 和 evidence ID。
- 点击“重放 Run”：展示 `parent_run_id/replay_id` 和输入哈希一致。Replay 是诊断动作，设计上不重复写入学习进度。

## 2:25–3:00 评测实验室：把两类证据分开

打开 `/lab`，先展示 **Agent Eval**，再切换 **Model Eval**：

- Agent Eval：5 个 Golden Cases、19 条固定检索 query、3 类 Tool timeout 和 3 条安全探针。固定回归的 Recall@1/3、Recovery、Checkpoint Replay 均为 100%，只证明该受控规则链路的回归稳定性。
- Model Eval：3 个 VLM、7 组 GPU Run、BF16/INT8/NF4、QLoRA、结构化 Prompt 与 DPO Artifact。模型实验是 10 张公开教学图像的 4/3/3 划分，冻结 test 仅 3 图；只报告该小样本比较，不外推为临床或泛化结论。

收尾： “业务闭环解决研修者怎么练，Agent 链路解决过程怎么追踪和恢复，评测实验室解决每个技术结论如何回到 Artifact。”
