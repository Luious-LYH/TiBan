## 面试问答准备

### Q1: 这个项目的核心技术亮点是什么？

**A**: 四模块信息架构、会话恢复机制、独立 ChatAgent Sidecar、BYOK 评测系统。

- **四模块架构**：清晰的职责分离，每个模块可独立深链
- **会话恢复**：通过 URL session_id 实现刷新不丢失进度
- **ChatAgent Sidecar**：响应式设计，桌面侧栏 + 移动端全屏
- **BYOK 评测**：用户自带 API Key，不落盘，一次性使用

### Q2: 如何保证代码质量和可维护性？

**A**: TypeScript 类型系统、组件化设计、文档驱动开发。

- **类型安全**：所有 API 有 TypeScript 类型定义
- **组件复用**：统一的按钮、卡片、输入框样式
- **文档完善**：PRD、实施进度、视觉规范、验收报告
- **代码规范**：ESLint、Prettier、Git commit 规范

### Q3: 移动端适配的难点是什么？如何解决？

**A**: ChatAgent 的展示方式和触控目标大小。

- **ChatAgent**：桌面固定 320px 侧栏，移动端 `fixed inset-0` 全屏覆盖
- **触控目标**：所有按钮 ≥ 44px，避免误触
- **响应式布局**：Tailwind 的 responsive utilities，375px 无横向滚动
- **测试方法**：Chrome DevTools + 真实设备测试

### Q4: 如何处理 API 失败和网络错误？

**A**: 分层错误处理 + 友好用户提示。

- **加载状态**：Spinner + 文字说明
- **错误页面**：AlertCircle 图标 + 错误描述 + 重试按钮
- **行内错误**：Amber 背景卡片 + 具体错误信息
- **降级策略**：后端不可用时使用前端 fallback 数据

### Q5: 下一步优化计划是什么？

**A**: FSRS 复习算法、SSE 流式输出、题库工厂。

- **FSRS**：科学复习间隔，提升学习效率
- **SSE**：实时流式输出，提升 ChatAgent 体验
- **题库工厂**：文档导入 → 自动生成 → Judge → 发布
- **多领域扩展**：从内镜扩展到其他医学领域
