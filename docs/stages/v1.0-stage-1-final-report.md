## Outcome

Stage 1 local implementation is complete and packaged for the `v1.0.0`
release tag. The main product path now demonstrates a deterministic,
memory-driven adaptive loop:

```text
Practice submit
  -> immutable Attempt
  -> LearnerMastery + FSRS ReviewCard
  -> next-session selection reads persisted state
  -> recommendation reason is returned to the learner
```

The Tutor remains a bounded single-agent runtime. It has read-only tools and
does not own grading, Attempt, mastery, or review scheduling writes.

## Implemented changes

### Adaptive Learning Loop

- Reused `AttemptModel`, `LearnerMasteryModel`, `ReviewCardModel`,
  `PracticeSessionModel` and `PracticeSessionItemModel`.
- Added server-authoritative session selection order: due review, weak topic,
  unseen coverage, then already attempted questions.
- Added selection strategy, reason and evidence to the current session
  response.
- Practice UI consumes the persisted session membership/order instead of a
  separate random question-list response.
- Added React StrictMode duplicate-session protection.
- Added read-only `get_recent_mistakes`; no LLM write tool was introduced.

### Tutor and retrieval evidence

- Preserved the bounded single-agent runtime, permissioned tools, ToolReceipt,
  AgentEvent and SSE path.
- Preserved pre-submit answer isolation and deterministic post-submit business
  writes.
- Added a reproducible 50-case `tutor-answer-eval-v1` fixture and protocol
  artifact without raw chain-of-thought, secrets or patient data.
- Re-ran the frozen retrieval benchmark and recorded the Dense default decision
  with latency trade-offs.
- Kept PostgreSQL as relational/citation authority and Qdrant as retrieval
  index; EndoBench remains evaluation-only.

### Release packaging

- Versioned frontend package and backend API as `1.0.0`.
- Added local alternate-port Compose override for clean-start acceptance; it
  does not alter the production topology.
- Added the final evidence report and preserved historical/user-owned files
  outside the Stage 1 commit.

## Safety and provenance boundary

- No secret, provider credential, private endpoint, raw chain-of-thought or
  patient-identifying data was persisted.
- Tutor answer access remains phase/permission controlled.
- Grading, Attempt, mastery and FSRS writes remain deterministic application
  workflow responsibilities.
- Adaptive and Tutor evaluation fixtures are synthetic/anonymous engineering
  evidence, not clinical validation.
- Medical output remains subject to: `仅供教学研修或医生复核前辅助，不作为独立诊断依据。`
- EndoBench is not eligible for Tutor retrieval, Question Factory evidence or
  direct user-ready QBank import.

## Known limitations and follow-up

1. Provider-backed Tutor quality scoring is **EXTERNAL PROVIDER ACCEPTANCE
   PENDING**. The checked-in 50-case run proves protocol and permission-path
   execution only; it intentionally does not invent model-quality scores.
2. RAG ground-truth and Judge labels still need independent manual review;
   current metrics are engineering benchmark evidence, not clinical evidence.
3. Hosted GitHub Actions remains pending until a remote and push authority are
   deliberately configured. The local checks above are not a substitute for a
   hosted run.
4. The frontend dependency install reports npm audit findings (1 critical,
   14 high and 1 moderate in the current lockfile resolution). Dependency
   remediation was not folded into this release because it would be a separate
   compatibility/security change.
5. The local clean-start stack is intentionally running on alternate ports
   because another developer stack occupies the default ports.
