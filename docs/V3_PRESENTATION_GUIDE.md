# v3 PPT 汇报指导

## 一句话故事

我们构建了一个面向多领域学习的 Agent-native 智能学习平台：模型评测、题库练习、智能辅导、资料检索和复习记忆共享同一条学习主线；Medical / Endoscopy 是默认演示领域，平台能力可以迁移到其他专业场景。

## 2-3 分钟视频脚本

1. 首页：展示平台定位和五步闭环，不讲后台实现。
2. 模型页：展示模型池和综合研修适配度，说明平台智能助手的选择依据。
3. 研修页：选择一道图像题，医生独立作答。
4. 提交后：展示得分、证据点、错因标签和下一题推荐。
5. 报告页：输入图片/所见，生成结构化报告草稿，再进行智能修改。
6. 画像页：展示能力雷达、成长曲线和下一步研修方向。

## 录屏前打开顺序

1. 后端使用 `8001` 启动，前端使用 `5173` 启动。
2. 浏览器只打开 `http://127.0.0.1:5173`。
3. 录屏顺序固定为：首页 -> 模型 -> 研修 -> 报告 -> 画像。
4. 研修页只演示一次作答和提交，看到证据复盘后立刻切到报告页。
5. 报告页生成草稿后，只演示一次“修改报告”，不要展开高级调试信息。
6. 全程只使用五个主导航：首页、模型、研修、报告、画像。

## 推荐时间分配

- 首页 20 秒：一句话定位和闭环。
- 模型 35 秒：为什么选择当前智能助手。
- 研修 55 秒：医生看图、作答、提交、证据复盘。
- 报告 35 秒：结构化草稿和智能修改。
- 画像 25 秒：能力沉淀和下一步研修。
- 收束 10 秒：先从内镜中心/住培基地试点落地。

## PPT 结构

### 第 1 页：痛点

传统学习流程常见问题：资料与题目彼此割裂、错因反馈不够细、学习进度难以沉淀为下一步行动。

### 第 2 页：方案

TiBan：模型评测 + 题库练习 + 智能辅导 + 复习记忆 + 领域扩展。

### 第 3 页：模型评估

讲清楚智能助手不是随便选择，而是经过统一数据资源上的多维评估：正确率、复杂题支持、证据完整性和错误前提识别。

### 第 4 页：医生研修

重点展示研修页。医生先作答，系统再给证据复盘和下一题推荐，形成可持续练习闭环。

### 第 5 页：报告辅助

展示报告生成和修改能力，强调它服务医生表达规范化，而不是替代医生诊断。

### 第 6 页：能力成长

画像页说明平台能沉淀医生能力曲线和薄弱项，具备持续使用价值。

## 讲述注意

- 不把默认演示领域误解为产品边界；统一强调 Domain Pack 与共享学习核心。
- 不把后台核验、工程测试作为主线。
- 不讲内部开发指令或页面制作策略。
- 不声称平台可独立诊断。
- 重点讲商业落地价值：低门槛研修、即时反馈、报告规范化、能力可量化。
